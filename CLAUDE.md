# CLAUDE.md

Project instructions for Claude Code. Read this before making any changes.

## What this is

A Node.js backend template with a harness-engineering overlay for AI coding agents. See `AGENTS.md` for the full operational contract.

## Bootstrap

```sh
npm ci || npm install
npm run worktree:bootstrap   # if working in a worktree
npm run dev:stack:up          # when you need DB, Redis, or observability
```

## Verify before declaring done

```sh
npm run verify
```

This runs: lint, format check, architecture inventory, docs validation, quality score, tests, and smoke tests.

## Key commands

| Task              | Command                                  |
| ----------------- | ---------------------------------------- |
| Start dev server  | `npm run start:dev`                      |
| Run tests         | `npm run test`                           |
| Smoke test        | `npm run test:smoke`                     |
| Lint + fix        | `npm run lint:fix`                       |
| Format            | `npm run format`                         |
| New migration     | `npm run migration:new -- --name=<slug>` |
| Run migrations    | `npm run migrate`                        |
| Migration status  | `npm run migrate:status`                 |
| Check plan claims | `npm run claim:check`                    |
| Start local stack | `npm run dev:stack:up`                   |
| Stop local stack  | `npm run dev:stack:down`                 |
| Quality score     | `npm run quality:score`                  |

## Project structure

```
bin/www           → entry point (clustering)
init.js           → master process init (DB bootstrap, cron)
app.js            → Express app setup
config/           → DB, env loading, migrations, startup guard
models/           → Sequelize models
migrations/       → Umzug schema migrations
middleware/       → auth, validation, rate limiting, errors
routes/v1/        → versioned API routes
controllers/v1/   → request handlers
service/v1/       → business logic + workflow engine
helper/           → auth, casbin, cron, mail, SMS, PDF, uploads
utils/            → constants, formatters, pagination, time
scripts/          → bootstrap, verification, plan helpers
docs/             → architecture, workflow, quality, security docs
```

## Request flow

```
bin/www → init.js → app.js → middleware → routes → controllers → services → models → DB
```

## Rules

- Read files before changing them.
- Keep changes small and verifiable.
- Extend existing patterns — don't create parallel ones.
- Use the existing bootstrap/startup flow (`bin/www` → `init.js` → `app.js`).
- Use the built-in Umzug migration system for schema changes. Don't add alternate migration tools.
- Use canonical integrations (see `AGENTS.md`) — don't introduce parallel libraries for uploads, SMS, mail, PDF, or pagination.
- Don't delete template features unless explicitly asked.
- Update docs when architecture or behavior changes.
- For multi-agent work: check `docs/exec-plans/active/`, run `npm run claim:check`, respect existing claims.

## Environment

- `.env.development` — default local config
- `.env.worktree` — worktree-specific overrides (auto-generated by bootstrap)
- `.env.local` — personal overrides (gitignored)
- Priority: `.env.local` > `.env.worktree` > `.env.{NODE_ENV}`

## DB safety

- `init.js` guards DB bootstrap — only runs against worktree-local DB unless `ALLOW_NON_LOCAL_STARTUP_DB_BOOTSTRAP=true`.
- Use `SKIP_STARTUP_MIGRATIONS=true` for local tasks that don't need DB.

## Testing

- Framework: Mocha + Supertest
- Test files: `test/**/*.test.js`
- Always run `npm run test` before committing.
